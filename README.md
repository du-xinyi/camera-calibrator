# camera-calibrator

基于 Qt 6 和 OpenCV 5 的桌面相机标定工具。从普通棋盘格或 ChArUco 图片中估计相机内参、畸变系数，以及每张图片的标定板位姿。

## 主要功能

- 支持 `Pinhole` 和 `Fisheye` 相机模型。
- 支持普通棋盘格与 ChArUco 标定板，内置多种 ArUco 字典。
- 普通棋盘格可选择传统方法（`Classic`）或扇区法（`Sector-Based`）角点检测。
- 标定、算法对比和批量去畸变均在后台执行，运行期间可取消。
- 对图片进行模糊、曝光、亮暗裁切及相似画面质量预检。
- 逐图区分读取失败、尺寸不一致、未找到标定板、有效角点不足和处理异常，失败图片保留在列表中。
- 显示整体 RMS、单图 RMS、内参、畸变系数和三维位姿分布。
- 显示角点覆盖热力图与逐角点重投影误差，辅助检查采样不足和高误差区域。
- 支持原图与去畸变图并排或分割线对比，同步缩放和平移查看局部效果。
- 标记高误差图片，支持排除后重新标定并比较 RMS 变化。
- 勾选图片控制是否参与标定，支持批量启停、恢复及按状态筛选。
- 保存和打开 `.calibration.json` 完整标定会话，恢复内参、误差、位姿及图片启用状态。
- 在关闭、清空、打开项目或导入参数前提醒保存未保存的修改。
- 算法对比后可一键应用成功候选，直接用于预览和导出。
- 导入、导出 OpenCV 兼容的 YAML 相机参数。
- 批量导出去畸变图片，并拒绝分辨率不匹配的输入。

## 环境要求

- Linux
- CMake 3.16 或更高版本
- 支持 C++17 的编译器
- Qt 6：`Widgets`、`Concurrent`
- OpenCV 5：`calib`、`geometry`、`objdetect`、`imgproc`、`imgcodecs`
- yaml-cpp 开发库（Debian / Ubuntu 包名为 `libyaml-cpp-dev`），用于读取 PyYAML 等工具生成的标准 YAML。

CMake 会尝试通过 `qmake6` 和常见安装目录自动定位 Qt 6，并优先使用系统中的 OpenCV 5 配置。

## 构建与运行

```bash
git clone https://github.com/du-xinyi/camera-calibrator.git
cd camera-calibrator
cmake -S . -B build
cmake --build build --parallel
./build/camera-calibrator
```

程序启动后显示“相机标定”主窗口。

如果 CMake 无法自动找到依赖，请显式提供安装位置：

```bash
cmake -S . -B build \
  -DCMAKE_PREFIX_PATH=/path/to/Qt/6.x/gcc_64 \
  -DOpenCV_DIR=/path/to/opencv5/lib/cmake/opencv5
```

## 快速开始

1. 点击“图片”或“文件夹”，加载至少 3 张标定图片。
2. 选择相机模型和标定板类型。
3. 按实际标定板填写方格数、方格尺寸，以及 ChArUco 的标记尺寸和字典。
4. 点击“标定”，等待角点检测与参数求解完成。
5. 检查整体 RMS、单图 RMS、位姿分布和去畸变预览。
6. 在位姿窗口中排除高误差图片，并根据需要重新标定。
7. 点击“导出”保存 YAML 参数。

图片列表中的颜色表示处理结果：绿色表示检测成功，红色表示读取、尺寸或角点检测等环节失败。失败项的名称下方显示分类，鼠标悬停可查看具体原因、尺寸或角点数量。黄色背景和 `⚠` 表示质量预检发现潜在问题；预检只作提示，不会自动排除图片。

## 标定配置

### 相机模型

针孔模型（`Pinhole`）使用 `cv::calibrateCamera()`，输出 5 个畸变系数：

```text
[k1, k2, p1, p2, k3]
```

鱼眼模型（`Fisheye`）使用 `cv::fisheye::calibrate()`，输出 4 个畸变系数：

```text
[k1, k2, k3, k4]
```

不要只根据最低 RMS 选择模型。针孔模型启用切向畸变后自由参数更多，可能在参与标定的数据上得到更低 RMS，但画面边缘的外推效果未必更好。选择模型时还应比较：

- 不同模型使用的有效图片和角点是否一致。
- 去畸变后边缘直线是否自然。
- 画面边缘是否出现异常拉伸或波浪。
- 更换部分图片后，内参与畸变系数是否稳定。

“算法对比”会对同一批启用图片运行候选组合：普通棋盘格比较 `Pinhole/Fisheye × Classic/Sector-Based`，ChArUco 比较两种相机模型。表格显示 RMS 和有效图片数，成功候选按 RMS 排序；选择时仍应结合去畸变效果和参数稳定性。即使图片相同，不同检测器的有效角点也可能不同。

在对比表格中选中成功的候选，点击“应用选中结果”，即可切换当前配置和标定结果，无需再次求解。失败的候选无法应用。

### 标定板参数

界面中的“方格数”表示完整方格数量：

- 普通棋盘格的行、列各至少 4 个方格，内部角点数为 `(列数 - 1) × (行数 - 1)`。
- ChArUco 使用完整方格数创建标定板模型。
- 方格尺寸和标记尺寸使用毫米，导出的平移向量也以毫米为单位。
- ChArUco 的标记尺寸必须小于方格尺寸，“标记字典”必须与实物一致。

`Classic` 和 `Sector-Based` 只决定普通棋盘格的角点检测方式。二者检测到角点后，仍由当前选择的 `Pinhole` 或 `Fisheye` 模型完成参数求解；`Sector-Based` 本身不是一套相机标定模型。

### 畸变选项

- 切向畸变：用于 `Pinhole`，控制是否估计 `p1`、`p2`。
- 轴倾斜：仅用于鱼眼模型；没有明确硬件依据时建议关闭。
- 径向系数个数：控制参与估计的径向畸变系数数量（`Pinhole` 2–3，`Fisheye` 2–4）。

修改模型、标定板参数、检测方法、畸变选项或标定图片后，旧标定结果会自动失效。

## 结果质量

### 误差提示

所有启用的图片共同参与标定，未勾选的图片不参与求解。至少启用 3 张图片后可以开始标定。

程序使用以下经验阈值进行提示：

- 整体 RMS 超过 `1.0 px` 时显示质量警告。
- 单图 RMS 超过 `2.0 px` 时标记对应图片。

阈值用于筛查，不是所有镜头和应用的统一合格标准。建议让标定板覆盖画面中心、边缘和四角，并包含不同距离、倾角和旋转方向。

图片列表中的勾选框控制是否参与标定、算法对比及批量去畸变导出。停用图片仍保留在项目中，可以继续查看，重新勾选即可恢复；右键支持批量启用、停用或恢复全部。位姿窗口中的“排除后重新标定”也使用停用方式，不会删除磁盘文件。启用状态变化后，旧标定结果会失效。

列表上方可以筛选全部图片、参与标定、已停用、质量提示或全部检测失败项，也可单独筛选读取失败、分辨率不符、未找到标定板和角点不足。筛选仅改变显示范围，不改变勾选状态；检测结果在预览或标定后更新。修改检测配置后会清除旧检测结论，读取失败提示仍会保留。

无法读取的图片仍保留路径和占位项，可以查看原因、停用或在修复原文件后选中图片重试。尺寸检查采用本次首张可读取图片作为基准；单图预览不会把批量检测中的尺寸冲突改成检测成功。

### 覆盖与误差诊断

完成标定后，点击工具栏或“视图”菜单中的“覆盖与误差”：

- 覆盖页将所有有效标定图片中的检测角点统计到网格中，展示覆盖比例、角点数量及未覆盖区域，帮助决定补拍位置。颜色表示角点采样密度；网格占用情况是采样提示，不代表标定结果已经合格。
- 误差页可以切换有效图片，查看原图上的检测角点、重投影点与偏差连线，并显示实际像素 RMS 和最大误差。误差向量支持放大显示，放大倍数不影响真实误差数值；滚轮缩放、拖动平移可检查局部角点。

诊断使用参与当前求解的观测数据。图片缺失或尺寸不匹配时，不会在错误的图像上叠加误差。

### 去畸变前后对比

完成标定或导入有效参数后，在图片列表选中一张图片，点击“去畸变对比”。可选择并排显示或拖动分割线查看原图与校正图，使用滚轮或按钮同步缩放、拖动平移，并通过“适应窗口”和“100%”调整视图。对比使用未叠加角点的图片；输入分辨率必须与参数一致。

带 EXIF 方向标记的照片按显示方向判断标定分辨率。批量导出时，若目标目录已有同名文件，程序会在新文件名末尾追加 `_2`、`_3` 等序号，保留原图和已有结果。

## 项目与参数文件

### 标定项目

“文件 → 保存项目”会将图片路径、启用状态、标定选项，以及当前有效的内参、畸变系数、重投影误差、位姿及结果说明写入 `.calibration.json`。图片和位姿引用的路径以项目文件目录为基准保存为相对路径，项目文件本身不包含图片内容。导入 YAML 后，也可以将参数保存为项目；没有有效结果时仅保存输入和配置。

首次保存会选择项目文件，之后“保存项目”直接保存到当前路径；“项目另存为”可选择新位置。只有配置、没有图片时，也可保存项目。成功标定中的逐图检测报告会随结果保存。

添加图片、修改配置或图片启用状态，以及标定或导入新结果后，窗口标题会标记未保存状态。关闭、清空、打开另一个项目或导入参数前会提供“保存／放弃修改／取消”。取消保存路径或保存失败时，原操作不会继续，当前内容仍保留。导出 YAML 不会代替项目保存；浏览图片、切换筛选和缩放视图不会标记项目修改。后台任务运行时需先完成或取消任务，再关闭窗口。

项目只读取当前版本 `3`，旧版本项目不再支持。重新打开保存的项目后，可以直接查看位姿、预览去畸变并导出参数。

标定结果还会在项目中保存检测角点和重投影点，重新打开即可继续查看覆盖与误差。导入的 YAML 不包含逐角点观测，需重新标定后才可使用诊断窗口；去畸变对比仍可使用有效参数。

保存时会记录图片的文件大小和修改时间。打开项目时若发现图片变化或缺失，会保留输入配置并提示旧结果失效，需重新标定或导入参数。修改图片启用状态或标定配置也会使已恢复的结果失效。

### YAML 参数

导入参数用于去畸变时，只需提供相机模型、宽度、高度、内参矩阵和畸变系数。以下是可直接导入的针孔模型示例。

```yaml
camera_model: pinhole
image_width: 1920
image_height: 1080
camera_matrix: [[820.0, 0.0, 960.0], [0.0, 821.0, 540.0], [0.0, 0.0, 1.0]]
distortion_coefficients: [-0.21, 0.05, 0.001, -0.001, -0.004]
```

鱼眼模型使用 `camera_model: fisheye` 和 4 个畸变系数。若提供 `format_version`，其值须为 `3`。标定板、求解选项、误差统计和位姿均可省略。界面将缺失的 RMS 和图片数显示为“未提供”，保存项目或再次导出会保留这些字段的缺失状态。

本程序完成针孔模型的 ChArUco 标定后，导出的 YAML 还包含求解所用的配置与统计，如下所示。

```yaml
format_version: 3
camera_model: pinhole
image_width: 1920
image_height: 1080
board_type: charuco
board_columns: 14
board_rows: 9
square_size_mm: 20.0
marker_size_mm: 15.0
aruco_dictionary: DICT_5X5_100
estimate_tangential_distortion: 1
radial_coefficients: 3
rms_reprojection_error: 0.42
quality_warning: 0
images_used: 12
images_total: 15
camera_matrix:
   - [ 820.0, 0.0, 960.0 ]
   - [ 0.0, 821.0, 540.0 ]
   - [ 0.0, 0.0, 1.0 ]
distortion_coefficients: !!opencv-matrix
   rows: 1
   cols: 5
   dt: d
   data: [ -0.21, 0.05, 0.001, -0.001, -0.004 ]
poses: []
```

如果提供 `poses`，每项须包含图片路径 `image`、三分量旋转向量 `rotation_vector`、三分量平移向量 `translation_vector` 和单图误差 `reprojection_error`。导出时按目标 YAML 所在目录计算图片相对路径，来自不同目录的同名图片各自保留对应位姿。

本程序导出时，`camera_matrix` 使用 3×3 嵌套数组，`distortion_coefficients` 使用 OpenCV `!!opencv-matrix` 行向量。

相机参数只适用于标定分辨率。图片尺寸不一致时，预览不会应用去畸变，批量导出也会跳过对应图片。

## 常见问题

### 无法检测标定板

确认填写的是完整方格数。使用 ChArUco 时，还要确认标记字典、方格尺寸和标记尺寸与实物一致。标定板应完整出现在画面中，并避免模糊、反光和严重过曝。

### 切换模型后无法勾选去畸变

模型或标定参数变化后，旧结果不再匹配，程序会清除并禁用去畸变状态。重新完成标定或导入匹配的 YAML 参数后即可启用。

### 参数偶尔变化很大

检查高 RMS 图片、图片分辨率、标定板尺寸和拍摄姿态分布。不要只为降低 RMS 随意开启轴倾斜或增加自由参数；先处理模糊、反光、重复姿态和边缘角点错误。

### CMake 找不到 Qt 6 或 OpenCV 5

确认安装了所需组件，并通过 `CMAKE_PREFIX_PATH` 或 `OpenCV_DIR` 指向对应的 CMake 包目录。如果缓存中保留了旧路径，请删除构建目录后重新配置。

## 项目结构

```text
src/
  main.cpp                          应用入口
  core/
    calibration.*                  标定、预览、参数导入导出和去畸变
    calibration_project.*          标定项目 JSON 读写
    image_quality.*                图片质量预检
  ui/
    algorithm_comparison_dialog.*  算法结果对比
    calibration_diagnostics_dialog.*  角点覆盖与重投影误差诊断
    image_comparison_dialog.*      去畸变前后对比与同步缩放
    mainwindow.*                   主界面与异步任务
    pose_result_dialog.*           单图误差、图片排除与三维位姿
```

## 验证

默认构建会生成会话读写、标定诊断及界面交互测试，可在构建后运行：

```bash
ctest --test-dir build --output-on-failure
```

界面测试使用 Qt 的 `offscreen` 平台，无需连接摄像头或显示器。仅构建应用时可在配置命令中添加 `-DBUILD_TESTING=OFF`。
